# 세션 인수인계 (Session Handoff)

세션 A가 하던 일을 세션 B가 질문 없이 바로 이어받게 하는 것이 목표다.
인수인계가 실패하는 원인은 거의 항상 같다: **"무슨 얘기를 했는지"만 적고 "다음에 정확히 뭘 해야 하는지"를 안 적기 때문.** 이 스킬의 모든 규칙은 그 실패를 막기 위한 것이다.

두 가지 모드가 있다. 사용자의 말을 보고 판단한다:
- 지금 하던 걸 넘기려는 말 → **저장 모드**
- 지난 작업을 이어받으려는 말 → **복원 모드**

---

## 저장 모드 — 인수인계 문서 만들기

### 1단계: 실제 상태 검증 (기억으로 쓰지 말 것)

문서를 쓰기 전에 반드시 현재 상태를 도구로 확인한다. 긴 세션에서는 기억이 실제와 어긋나 있는 경우가 많고, 잘못된 경로 하나가 다음 세션 전체를 헤매게 만든다.

1. `git status`로 변경된 파일 목록 확인 (git 저장소인 경우)
2. 이번 세션에서 만들거나 수정한 핵심 파일이 실제로 그 경로에 존재하는지 확인
3. 작업 중이던 파일이 "완성 상태"인지 "수정하다 만 상태"인지 실제 내용을 열어 확인

### 2단계: 인수인계 문서 작성

저장 위치: `{프로젝트 루트}/_handoff/YYYY-MM-DD_HHMM_{주제}.md`
(`_handoff` 폴더가 없으면 만든다. 주제는 파일명에 쓸 수 있게 짧게. 날짜·시각은 기억이 아니라 `date` 등 도구로 확인해서 쓴다.)

경로 표기 기준: 프로젝트 안 파일은 루트 기준 상대 경로, 프로젝트 밖 파일(다른 프로젝트의 규칙 파일 등)은 절대 경로로 적는다. 커밋 안 된 변경은 그대로 두고 넘긴다 — 커밋 여부는 사용자가 정하는 일이다.

아래 템플릿을 그대로 따른다. 순서가 중요하다 — 다음 세션은 위에서부터 읽고, 1~2번만 읽어도 일을 시작할 수 있어야 한다.

```markdown
# 인수인계 — {주제}

작성: YYYY-MM-DD HH:MM
프로젝트: {프로젝트 루트 절대 경로}

## 1. 지금 하던 일 (한 줄)

{전체 목표를 한 문장으로}

## 2. 바로 다음 할 일

{새 세션이 아무 질문 없이 즉시 실행할 수 있는 구체적 행동.
반드시 실제 파일 경로 포함. "계속 진행" 같은 모호한 표현 금지.
주 행동은 1개로 명확히 하되, 바로 이어지는 후속 작업이 있으면 "완료 후 이어서 ~"로 함께 적는다.
예: "src/login.js 의 비밀번호 검증 함수에 실패 횟수 제한을 추가한다. 완료 후 이어서 안내 문구를 수정한다."}

## 3. 진행 상황

- ✅ {완료된 일}
- 🔄 {하다 만 일 — 어디까지 했는지 정확히}
- ⬜ {아직 안 한 일}

## 4. 작업 중인 파일 상태

| 파일 (경로) | 상태 |
|------------|------|
| {경로} | {완성 / 수정 중 — 어느 부분까지 / 미생성} |

## 5. 이번 세션에서 정한 것 (결정사항)

{대화 중에 확정됐지만 아직 파일에 반영 안 된 결정을 빠짐없이.
기각된 안도 "~는 하지 않기로 함 (이유)"로 적는다 —
다음 세션이 같은 제안을 반복하지 않도록.}

## 6. 사용자 지적·주의사항

{이번 세션에서 사용자가 고치라고 한 것, 하지 말라고 한 것.
다음 세션이 같은 실수를 반복하면 안 되는 항목들.}

## 7. 시작할 때 열어볼 파일

{다음 세션이 맥락 잡는 데 필요한 파일 경로 2~4개, 각각 왜 여는지 한 줄}
```

작성 요령:
- **2번이 이 문서의 심장이다.** 여기만 읽고도 일을 시작할 수 있어야 한다. 검토·판단이 필요한 상태면 "무엇을 어떤 기준으로 판단해야 하는지"까지 적는다.
- **5번과 6번이 가장 자주 누락되고, 누락됐을 때 가장 아프다.** 대화 속에서만 정해진 규칙은 세션이 끝나면 세상에서 사라진다. 파일 어딘가에 이미 기록된 건 경로만 적고, 대화에만 있는 건 전부 옮겨 적는다.
- 대화 요약이나 경위 설명은 쓰지 않는다. 다음 세션에 필요한 건 역사가 아니라 현재 상태와 다음 행동이다.

### 3단계: 마무리 안내

문서를 저장한 뒤 사용자에게 알린다:
1. 저장된 파일 경로
2. "다음 세션에서 **'인수인계 받아서 이어서 해줘'** 라고만 하시면 됩니다"

## 복원 모드 — 인수인계 받기

### 1단계: 최신 인수인계 문서 찾기

현재 프로젝트의 `_handoff/` 폴더에서 파일명 타임스탬프 기준 가장 최신 문서를 읽는다.
사용자가 특정 주제를 언급하면 그 주제의 문서를 찾는다.
폴더나 문서가 없으면 그렇다고 말하고, 무엇을 이어서 하고 싶은지 묻는다.

### 2단계: 현재 상태 대조

문서가 작성된 뒤 상황이 바뀌었을 수 있다 (사용자가 직접 파일을 고쳤거나, 다른 세션이 작업했거나). 문서의 "4. 작업 중인 파일 상태"에 적힌 파일들을 실제로 확인해서 문서 내용과 맞는지 대조한다. 어긋난 게 있으면 브리핑에서 언급한다.

프로젝트 규칙 파일(CLAUDE.md 등)과 기존 작업물이 어긋나는 걸 발견해도 임의로 통일하지 않는다. 인수인계된 작업을 기존 작업물의 톤·형식에 맞춰 진행하고, 어긋남은 브리핑에서 한 줄로만 언급해 사용자가 판단하게 한다.

### 3단계: 3줄 브리핑 후 바로 착수

사용자에게 딱 3줄로 브리핑한다:
1. 하던 일: {1번 요약}
2. 바로 할 일: {2번 요약}
3. 주의사항: {6번 중 핵심 1개, 없으면 생략}

그리고 **"2. 바로 다음 할 일"을 즉시 시작한다.** 이때 지킬 것:
- 문서의 "5. 결정사항"에 있는 내용을 다시 질문하거나 다른 안을 제안하지 않는다. 이미 끝난 논의다.
- "6. 사용자 지적"은 이번 세션 내내 유효한 규칙으로 취급한다.
- 문서에 없는 정보가 꼭 필요할 때만 질문한다.

### 완료된 인수인계 정리

"완전히 끝"의 기준은 문서의 "3. 진행 상황"에 있는 ⬜ 항목이 전부 끝났거나 사용자가 끝났다고 확인한 시점이다 ("2. 바로 다음 할 일"만 끝낸 것은 부분 완료). 완전히 끝나면 해당 인수인계 문서를 `_handoff/완료/` 폴더로 옮긴다. 부분 완료 상태에서 세션을 또 넘겨야 하면, 옮기지 말고 저장 모드로 새 인수인계 문서를 만든다 (세션이 계속되는 동안에는 만들 필요 없다).
